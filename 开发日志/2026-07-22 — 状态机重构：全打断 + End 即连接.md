# 开发日志

## 2026-07-22 — 状态机重构：全打断 + End 即连接

### 改动背景

原状态机中点击互动只在 `IDLE` / `SKILL_IDLE` 状态下生效，其他状态点击被静默忽略。同时 `SKILL_ATTACKING` 播完后 50% 直接跳回 `SKILL_IDLE`（跳过 End 动画），视觉上技能攻击→待机之间缺乏过渡。

### 改动内容

**1. handleClick 改为全打断（`usePetState.ts`）**

原：只有 `s === "IDLE"` 或 `s === "SKILL_IDLE"` 时才触发攻击

新：除 `DYING` 外，任何状态点击都立即打断当前动画进入攻击。同步清空 `pendingAutoSkill`、`excludeSkill`，防止打断后残留自动切换导致预期外行为。

**2. SKILL_ATTACKING → 100% 走 SKILL_ENDING**

原：50% 直回 `SKILL_IDLE`（不播 End），30% 走缓冲+End 退出，20% 走缓冲+End 切技能

新：每次技能攻击播完都先播 End 动画（`SKILL_ENDING`），End 之后只有两条路：
- `pendingAutoSkill` 有值 → `SKILL_BEGINNING`（切新 skill）
- `pendingAutoSkill` 无值 → `IDLE`（退出技能，`currentSkill = "none"`）

**3. 排除来源防止来回弹跳**

新增 `excludeSkill` ref。在 `SKILL_ATTACKING` 中决定切换目标时，排除当前 skill 和 `excludeSkill`（上次来源）。只有 2 个 skill 时最多切一次就回落 IDLE，杜绝 3→2→3→2 来回切换。

**4. 切换概率 30%**

新增 `STATE_CONFIG.P_skill_switch: 0.3`，End 播完后 30% 概率尝试切技能，70% 直接回 IDLE。

**5. 清理死代码**

- 移除 `keepSkillAfterEnd`（不再需要"保留当前技能"路径）
- 移除 `P_exit_to_idle`、`buffer_extra_loops`（不再使用）
- 重命名 `P_skill_attack` → `P_skill_switch`
- `BUFFERING` 状态、`clickQueued`、`bufferTarget` 等成为死代码暂留

### 验证

- 快速连点互动：攻击动画中立即被下一次点击打断，不等播完
- 技能动画中点击：直接播技能攻击，不等到技能收尾
- STARTING 动画中点击：跳过开场直接进入攻击
- DYING 中点击：仍忽略
- End 动画必定播放，不再跳过
- 3→2→3 来回弹跳不再发生
