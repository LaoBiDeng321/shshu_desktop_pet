# 对话总结：IPC 崩溃修复（全面修复 + 打包注意事项）

> 日期：2026-07-22
> 问题：用户把打包后的 exe 发给别人，对方电脑启动时闪退
>
> 报错：
> ```
> Uncaught Exception:
> TypeError: Error processing argument at index 0, conversion failure from
> at IpcMainImpl.<anonymous>
> ```
> 第一次修复（仅修 `setIgnoreMouseEvents`）没有解决，换了英文用户名报错依旧。

---

## 1. 崩溃原因

**根因**：Electron 的 V8 ValueSerializer **不能序列化 `undefined` 作为 IPC 参数**。渲染进程通过 `ipcRenderer.send()` 或 `ipcRenderer.invoke()` 传了 `undefined` 给主进程时，主进程侧反序列化直接崩溃。

**为什么第一次修复没解决**：`setIgnoreMouseEvents` 只是其中一个入口。`sendPanelAction`、`setAlwaysOnTop`、`reportAlwaysOnTop`、`resizeWindow`、`setPanelSize` 等十几个 IPC 通道都可能收到 `undefined`，只修一处没用。

**为什么换英文用户名还崩**：因为问题不在于用户名编码，而确实是 `undefined` 从某个 IPC 通道传进来了。

---

## 2. 修复方案（双层防御）

### 第一层：渲染进程发送端（preload.cjs / preload.ts）

所有 `ipcRenderer.send()` 和 `ipcRenderer.invoke()` 加 `safeSend()`/`safeInvoke()` 包装，**先把 `undefined` 替换成 `null` 再发送**：

```js
function safeSend(channel, ...args) {
  const safe = args.map(a => a === undefined ? null : a);
  ipcRenderer.send(channel, ...safe);
}
function safeInvoke(channel, ...args) {
  const safe = args.map(a => a === undefined ? null : a);
  return ipcRenderer.invoke(channel, ...safe);
}
```

`null` 是 structured clone 算法原生支持的值，不会触发序列化错误。

### 第二层：主进程接收端（main.ts）

所有 IPC handler 在调用 C++ Electron 方法（`setPosition`、`setBounds`、`setAlwaysOnTop` 等）前加类型/NaN 防御，防止异常值扩散：

| Handler | 加的防御 |
|---|---|
| `window-drag-move` | `typeof dx !== "number" \|\| isNaN(dx)` → 跳过 |
| `resize-window` | `typeof width !== "number" \|\| isNaN(width)` → 跳过 |
| `set-always-on-top` | `typeof on !== "boolean"` → 跳过 |
| `report-always-on-top` | `typeof on !== "boolean"` → 跳过 |
| `report-debug` | `typeof on !== "boolean"` → 跳过 |
| `panel-drag-move` | `typeof dx !== "number" \|\| isNaN(dx)` → 跳过 |
| `set-panel-size` | `typeof width !== "number" \|\| isNaN(width)` → 跳过 |
| `report-frame-rate` | `typeof rate !== "number" \|\| isNaN(rate)` → 跳过 |

### 涉及文件

| 文件 | 改动 |
|------|------|
| `electron/preload.cjs` | 新增 `safeSend`/`safeInvoke`，所有 IPC send/invoke 都经过它过滤 undefined→null；移除旧的 `setIgnoreMouseEvents` 单独手写 undefined 判断 |
| `electron/preload.ts` | 同步 TS 源码，保持一致 |
| `electron/main.ts` | 8 个 IPC handler 加类型/NaN 防御 |
| `release/更新说明.txt` | 追加 2.07 更新说明 |

### 验证

- 对比：之前 `setIgnoreMouseEvents` 修完后用户换英文用户名仍崩溃 → 本次全面修复后应不再触发
- 防御性：即使渲染进程某个新功能意外传了 `undefined`，`safeSend` 也会自动转成 `null`，不会崩溃
- 防御深度：即使 `safeSend` 漏了某个通道，main.ts handler 的类型检查也会拦截异常值进入 C++ 方法

## 7. 第二轮修复：Index 1 崩溃（同日第二轮）

### 背景

第一轮修复（`undefined` → `null`）解决了 `index 0` 崩溃，但用户发出去后仍有报错，报错变成了 `index 1`：

```
TypeError: Error processing argument at index 1, conversion failure from
```

堆栈中路径为 `C:/Users/LAOLIU~1/AppData/Local/Temp/...`（中文用户名的短文件名）。

### 触发场景

- **本机 `pnpm dev` 正常**，无法复现
- **打包后 exe** 在用户环境崩溃
- **快速切换 Windows 账号**后极易触发
- 用户注意到 DevTools 左上角出现原始文本 `` `r`n`r`n ``（不是换行符，是字面 ASCII 字符）

### 7.1 新增根因

1. **IPC 字符串含控制字符**：V8 ValueSerializer 在部分环境下（Temp 目录、中文短文件名、用户切换后的权限状态）处理含 `\r\n` 或其他控制字符的字符串时崩溃

2. **模板中残留字面文本**：`PetCanvas.vue` 两个 HTML 注释之间被意外写入了 `` `r`n`r`n `` 这 8 个可见 ASCII 字符，Vue 直接渲染到 DOM 中

3. **无单实例锁**：用户切换账号后旧进程残留，新实例与旧实例 IPC 通道冲突

4. **`preload-anim.ts` 裸 IPC**：动画窗口预加载使用裸 `ipcRenderer.send()`，无任何防护

### 7.2 修复内容

#### A. 字符串消毒层（preload.cjs / preload.ts / preload-anim.ts）

新增 `sanitizeIPC()` 递归函数，所有 IPC 参数在发送前统一处理：

```js
function sanitizeIPC(value) {
  if (typeof value === 'string') {
    return value
      .replace(/\r\n/g, ' ')          // CRLF → 空格
      .replace(/[\r\n]/g, ' ')        // 单独 CR/LF → 空格
      .replace(/[\x00-\x08\x0B\x0C\x0E-\x1F]/g, '');  // 其他控制字符 → 移除
  }
  if (Array.isArray(value)) return value.map(sanitizeIPC);
  if (value !== null && typeof value === 'object'
      && !(value instanceof Date) && !Buffer.isBuffer(value)) {
    const out = {};
    for (const [k, v] of Object.entries(value)) out[k] = sanitizeIPC(v);
    return out;
  }
  return value;
}
```

集成到 `safeSend`/`safeInvoke`：`undefined→null` 之后再过 `sanitizeIPC`。

#### B. 模板清理（PetCanvas.vue）

第 1896 行两个注释之间删除字面 `` `r`n`r`n `` 字符，替换为正常换行。

#### C. CSS 兜底

`.error-capture__item` 新增 `white-space: pre-wrap`，确保错误信息中即使有换行符也能正确渲染。

#### D. 主进程转发器加固（main.ts）

- `panel-action` 和 `panel-state` 转发前增加 `JSON.parse(JSON.stringify(data))`，剥离 Vue proxy 和非可克隆值
- `panel-state` 三个 `webContents.send` 各自独立 `try/catch`，一个窗口失败不阻塞其余两个

#### E. 单实例锁（main.ts）

```ts
const gotTheLock = app.requestSingleInstanceLock();
if (!gotTheLock) { app.quit(); }
else {
  app.on('second-instance', () => {
    if (mainWindow) { mainWindow.show(); mainWindow.focus(); }
  });
}
```

#### F. Temp 目录清理（main.ts）

启动时扫描 `%TEMP%` 中的旧便携版解压目录（含 `index.html` 或 `.exe` 的目录），清理除当前实例外的残留。

#### G. TypeScript 类型同步（types/index.ts）

补充 `showActionPanel`、`panelDragStart/Move/End`、`setPanelSize`、`requestPanelState` 等缺失类型。

### 7.3 防御架构（最终态）

```
渲染进程 IPC 调用
    │
    ▼
preload.cjs safeSend / safeInvoke
    ├── ① undefined → null
    └── ② sanitizeIPC() ← ★ 递归消毒 \r\n 和控制字符
    │
    ▼
main.ts ipcMain handler
    ├── ③ typeof/NaN 类型守卫（第一轮已有）
    ├── ④ JSON.parse(JSON.stringify()) 深度净化（panel-action/state）
    ├── ⑤ 逐窗口独立 try/catch（panel-state）
    ├── ⑥ requestSingleInstanceLock() ← ★
    └── ⑦ Temp 残留清理 ← ★
```

**2026-07-23 改动**：加了三种打包方式，可以根据需要选择：

| 命令 | 产物 | 特点 |
|------|------|------|
| `pnpm run pack` | `release/方舟桌面宠物-x.x.x.exe` | 单文件便携版，运行解压到 `%TEMP%`（原方式） |

- NSIS 配置：`oneClick: false` + `allowToChangeInstallationDirectory: true` 让用户可以选安装路径
- 三个 pack 命令共享同一个 version 自增逻辑，各自独立打包

**文件夹版使用方式**（给用户）：

## 8. v2 互动状态机 — 数据驱动版（2026-07-23）

### 动机

旧状态机硬编码了 `Attack_1` / `Skill_2_Begin` / `Skill_3_End` 等固定动画名，只覆盖了最简单的英文命名模式。实际干员 Spine 动画命名极其多样：

- 中文名：`攻击_开始` / `技能_循环` / `Reload_结束`
- 方向变体：`攻击_向下_开始`（与 `攻击_开始` 并存）
- 多段嵌套：`技能_向下_二_Reload_循环`（技能+方向+编号+子动作+阶段）
- 多种循环变体：`Skill_3_循环_A` / `Skill_3_循环_B`
- 子动作：`Skill_2_Reload_开始`（技能 2 内嵌 Reload）

旧系统对这些完全无法覆盖，互动永远只播 Attack_1 / Attack_2。

### 设计方案

新增 **`useAnimClassifier.ts`**，在角色加载时自动扫描动画列表，按**阶段后缀**分组：

| 后缀 | 映射阶段 |
|------|---------|
| `_开始` `_Begin` `_Start` | begin（起手） |
| `_循环` `_Loop` `_循环_A/B` | loop（循环） |
| `_结束` `_End` | end（收招） |
| `_待机` `_Idle` | idle（待机） |
| `_Break` | break（中断） |

**方向变体合并**：`攻击_向下_开始` 自动并入 `攻击` 组（方向词表：向下、向上、Down、Up、Front、Back）。

### 新状态机（精简版）

旧：9 种状态（STARTING / IDLE / ATTACKING / BUFFERING / SKILL_BEGINNING / SKILL_IDLE / SKILL_ATTACKING / SKILL_ENDING / DYING）
新：**4 种状态**（STARTING / IDLE / INTERACTING / DYING）

```
STARTING → IDLE → INTERACTING → IDLE
               → DYING
```

**点击流程**：
1. 分类器结果中优选完整三阶段序列（有 begin + loop）
2. 播 begin（单次）→ loop（2~3 轮）→ end（单次）
3. 结束后 30% 概率链到另一个序列（排除当前）
4. 否则回 IDLE

**中断处理**：点击立即打断当前动画，开始新序列。Spine 的 `setAnimation` 自动替换 track 0，配合 `seqGeneration` 计数器防止过期回调干扰。

### 旧代码移除

- `usePetState.ts` 从 ~470 行缩减到 ~230 行
- `onInteractClickInBar` 中基建模式的特殊选取逻辑删除，统一走 `handleClick()`
- `hasUsableSkill()` / `findAnim()` / `batchSwitch` / `pendingAutoSkill` / `excludeSkill` 等不再需要

| 文件 | 改动 |
|------|------|
| `src/features/pet/useAnimClassifier.ts` | **新增** — 动画分类器，~160 行 |
| `src/features/pet/usePetState.ts` | **重写** — 精简状态机，~230 行 |

## 9. 补丁：logToMain 统一走 sanitizeIPC（2026-07-23）

### 背景

在此之前，`logToMain()` 在 preload.ts / preload.cjs / preload-anim.ts 中使用裸 `ipcRenderer.send('log-entry', ...)`，**不经过 safeSend 的 sanitizeIPC 消毒**。虽然日志链路有全程 try/catch 兜底，且嵌套 `undefined` 不会触发 V8 ValueSerializer 崩溃，但从防御一致性角度来说这是一个缺口。

### 改动

3 个文件中的 `logToMain` 统一改为：

```ts
const safe = [level, source, message, data].map(a => a === undefined ? null : a).map(sanitizeIPC);
ipcRenderer.send('log-entry', ...safe);
```

```

    │
    ▼
preload.cjs safeSend / safeInvoke / logToMain  ← now all 3 go through sanitizeIPC
    ├── ① undefined → null
    └── ② sanitizeIPC() — 递归消毒 \r\n、控制字符、异常浮点数
    │
    ▼
main.ts ipcMain handler
    ├── ③ typeof/NaN 类型守卫
    ├── ④ JSON.parse(JSON.stringify()) 深度净化

    ├── ⑥ requestSingleInstanceLock()
    └── ⑦ Temp 残留清理

process.on('uncaughtException')
    └── ⑧ 最后防线日志
```
